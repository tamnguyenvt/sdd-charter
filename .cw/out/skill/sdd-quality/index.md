The quality pass. It reads and runs; the one file it writes is
`<spec folder>/quality.md` (`.sdd/settings.json`), from [sdd-quality-doc](../../template/sdd-quality-doc/index.md),
besides the links `link` adds.

1. **Read** — `spec.md`, every `spec-<key>.md`, `plan.json`, and the
   `quality.md` already there, whose grades become each new grade's
   `(was …)`; a grade with none before is `(new)`.
2. **Gather** — run `check` of [sdd-specs](../../script/sdd-specs/index.md) and /sdd-analyze; run every test
   and static check the project defines twice, the way the baseline does.
   A failure a story's handoff note records as known is still a finding,
   named as known.
3. **Grade** — each spec with a `Done` story, on its `Done` stories only, A–F
   per criterion:
   - **Verification passing** — each `Done` story has evidence in
     `plan.json`, each of its scenarios is held by a test that would fail
     without it or by the run its evidence names, and the checks pass now.
   - **Agent understandability** — its stories, FR and SC read cold, with no
     error /sdd-analyze reports, no vague word with no target, no
     `[NEEDS CLARIFICATION]`.
   - **Test stability** — the tests of its stories pass both runs; none
     skipped or passing one run and failing the other.
   - **Boundaries kept** — the code of each `Done` story does what its FR say
     and no more, and no later story bent an FR it cites.
   - **Conventions followed** — the spec keeps [sdd-spec-format](../../guide/sdd-spec-format/index.md), and the
     code of its stories keeps the guides that apply to it.

   A: nothing found. B: warnings only. C: one fault. D: two or more. F: the
   criterion fails outright — a check fails, a `Done` scenario nothing
   proves, a test that fails both runs. **Overall**: the five as A 4 to F 0,
   averaged and rounded down. A spec with no `Done` story is `—` on every
   one. Each grade carries its reason, citing the stories, FR or SC behind
   it; "nothing found" where there is nothing.
4. **Write** `quality.md`, never with the template's closing
   `Generated by` comment: the table, a section per spec, and **Lowest** — the
   spec with the lowest overall A–F, every one tied in `spec.md` order; a
   spec graded `—` is never it, and **Lowest** is `none` where every spec is. Run `link`, then `check` of [sdd-specs](../../script/sdd-specs/index.md), until
   it passes.
5. **Offer the cleanup** — name the lowest-graded part with its findings, and
   offer to fix each one: a fault in the code through /sdd-bug-fix, one in
   the spec through /sdd-plan. The user picks which, or none; the pass is
   done once they have answered.

Say in a few lines what changed since the last pass: each grade that dropped,
and why.
